# Vite 환경변수와 빌드 모드: .env는 값을 숨기지 않는다

## 개념 정의

프론트엔드 프로젝트에서 API 주소나 키를 코드에 직접 적는 대신 `.env` 파일로 빼는 건 거의 반사적으로 하는 일이다. 그런데 그렇게 하는 이유를 물으면 대개 두 가지가 섞여서 나온다. **환경마다 값을 갈아 끼우기 위해서**와 **비밀값을 숨기기 위해서**다.

앞의 것은 맞고, 뒤의 것은 틀렸다. `.env`와 `.gitignore`가 막는 건 **Git 저장소에 값이 올라가는 것**이지, **배포된 번들에서 값이 읽히는 것**이 아니다. 이 둘은 다른 경로이고, 프론트엔드에서는 후자를 막을 방법이 없다.

## 동작 원리

Vite는 프로젝트 루트의 `.env*` 파일을 읽고, 그중 **`VITE_` 접두사가 붙은 변수만** 클라이언트 코드에 노출한다.

```bash
VITE_API_URL=https://api.example.com    # 코드에서 읽힌다
DB_PASSWORD=hunter2                      # 읽히지 않는다 (undefined)
```

이 접두사 규칙은 편의 기능이 아니라 안전장치다. 서버용 값이 실수로 번들에 섞여 들어가는 걸 막으려고, **"이 값은 공개돼도 된다"를 개발자가 명시적으로 선언하게 만든 것**이다. 뒤집어 말하면 `VITE_`를 붙이는 행위 자체가 공개 선언이다.

코드에서는 `import.meta.env`로 읽는다.

```js
const apiUrl = import.meta.env.VITE_API_URL
```

핵심은 **`import.meta.env`가 런타임에 파일을 읽는 게 아니라는 것**이다. Vite는 빌드 시점에 이 표현식을 실제 값으로 **치환**한다. 참조가 아니라 문자열 삽입이다. 빌드가 끝나면 `.env` 파일은 결과물과 아무 관계가 없고, 값은 이미 JS 파일 안에 리터럴로 들어가 있다.

빌드 모드는 이 치환에 쓸 `.env` 파일을 고르는 스위치다.

```json
"scripts": {
  "build:staging": "vite build --mode staging",
  "build:production": "vite build --mode production"
}
```

`--mode staging`이면 `.env.staging`을, `--mode production`이면 `.env.production`을 읽는다. 소스는 한 줄도 안 고치고 산출물만 달라진다. 여기까지가 환경변수가 실제로 해 주는 일이다.

## 직접 확인한 예시

치환이라는 말을 믿고 넘어가는 대신, 빌드 결과물에서 값을 직접 찾아봤다. 검색으로 구분되는 고유한 표식 문자열을 키 자리에 넣고 빌드한 뒤 `dist/`를 뒤지는 방법이다.

```bash
echo 'VITE_OPENWEATHER_API_KEY=CLAUDE_SENTINEL_9f3a7b21' > .env.local
npm ci && npm run build
grep -rl "CLAUDE_SENTINEL_9f3a7b21" dist/
```

```
dist/assets/index-D1aCa7kB.js
dist/assets/WeatherDetailView-DW-zx28-.js
```

박힌 모양은 이랬다.

```js
...,a=Wt(`카드를 클릭하거나 검색해 보세요.`),o=`CLAUDE_SENTINEL_9f3a7b21`,s=[{query:`Seoul`,...
```

소스의 `import.meta.env.VITE_OPENWEATHER_API_KEY`가 빌드 후에는 짧은 변수에 담긴 평범한 문자열 리터럴이 됐다. 어디서 온 값인지를 알려주는 흔적은 남지 않는다 — 값만 남는다.

**예상과 달랐던 건 파일이 하나가 아니라 두 개였다는 점이다.** 메인 청크뿐 아니라 라우트 단위로 코드 스플리팅돼 나중에 불러오는 청크에도 같은 값이 복제됐다. 그 값을 쓰는 파일마다 사본이 생긴다는 뜻이다. 번들이 한 덩어리가 아니니까 안 보일 거라는 식의 기대는 성립하지 않는다.

확인 자체는 30초면 된다. 배포된 사이트에서도 개발자 도구 → Sources → 번들 파일에서 `Ctrl+F`로 같은 걸 할 수 있다.

### 그래서 무엇을 넣어도 되는가

| 넣어도 되는 것 | 넣으면 안 되는 것 |
|---|---|
| API 주소 (`VITE_API_URL`) | LLM·결제 등 과금되는 API 키 |
| 빌드 모드 표시 | DB 접속 정보 |
| 도메인 제한이 걸린 공개 지도 키 | 결제 시크릿 키 |
| 기능 플래그 | 서명용 개인키 |

판단 기준은 한 줄로 정리된다. **이 값이 화면에 그대로 인쇄돼도 괜찮은가.**

키를 지키는 유일한 방법은 애초에 브라우저로 안 내려보내는 것이다.

```
브라우저 ──(내 API 키)──▶ 외부 API          ← 키가 공개된다
브라우저 ──(사용자 토큰)──▶ 내 백엔드 ──(API 키)──▶ 외부 API
                                  ↑ 키는 여기서만 산다
```

## 자주 발생하는 오류

- **`import.meta.env.API_URL`이 `undefined`다.** `VITE_` 접두사가 없어서 아예 주입되지 않은 경우다. 오타가 아니라 규칙이다.
- **`.env`를 고쳤는데 화면이 그대로다.** 개발 서버 재시작이 필요하다. HMR 대상이 아니고, 프로덕션이라면 다시 빌드해야 한다. 빌드 시점에 박히는 값이라 런타임에 바꿀 방법이 없다.
- **로컬에선 되는데 배포 후 API 호출이 실패한다.** 빌드할 때 `--mode`를 안 줘서 기본 `.env`가 들어간 경우가 흔하다. 산출물에서 주소 문자열을 `grep`해 보면 바로 확인된다.
- **키가 이미 GitHub에 올라갔다.** 파일을 지워도 커밋 이력에 남으므로 해결되지 않는다. 폐기하고 재발급하는 게 유일한 답이다 → [.gitignore와 비밀정보 관리](../github-collaboration/gitignore-and-secrets.md)

## 프로젝트 적용

Vue 실습으로 만든 날씨 앱이 정확히 위험한 구조였다. 브라우저가 날씨 API를 직접 호출하고, 키는 `VITE_` 환경변수로 주입한다. 무료 API라 실질적 피해는 없지만 **구조만 놓고 보면 유료 LLM API를 그대로 프론트엔드에서 부르는 것과 같다.** 누군가 번들에서 키를 긁어 내 계정으로 호출하면 청구서는 나에게 온다.

여기서 얻은 실무적인 결론이 두 가지다.

- **`.gitignore`에 `.env*`를 넣는 건 여전히 필요하다.** 노출 경로가 둘인데 하나를 막는 것도 의미가 있다. 문제는 그게 전부라고 믿는 것이다. 어떤 변수가 필요한지는 `.env.example`을 대신 커밋해서 공유한다.
- **AX 서비스를 만들 때 첫 번째로 결정해야 하는 게 이거다.** LLM을 프론트에서 직접 부를 것인가, 백엔드를 경유할 것인가. 프론트에서 부르면 개발이 빠르고 서버가 필요 없다. 그리고 키가 공개된다. 프로토타입이라도 이 결정을 미루면 나중에 구조를 갈아엎게 된다.

빌드 후에도 값을 바꿔야 하는 경우 — 예를 들어 고객사마다 API 주소가 다른 경우 — 는 환경변수로 풀 수 없다. `public/config.json`을 두고 앱 시작 시 `fetch`로 읽는 방식을 쓴다. `public/` 아래 파일은 빌드가 가공하지 않고 그대로 복사하므로 배포 후에 교체할 수 있다.

## 배운 점

환경변수를 쓰면 값이 안전해진다고 막연히 생각하고 있었다. 표식 값을 넣고 빌드 결과물을 검색해 보니 그 생각의 정확한 경계가 보였다. **`.env`가 막는 건 "파일이 저장소에 올라가는 것"이고, 막지 못하는 건 "값이 브라우저로 내려가는 것"이다.** 파일이 안 올라가는 것과 값이 안 나가는 것은 다른 문제인데, `.gitignore`에 한 줄 추가하고 나면 둘 다 해결된 기분이 든다.

번들이 두 개 나온 것도 이 실험이 아니었으면 몰랐을 것이다. 코드 스플리팅은 성능 최적화 얘기로만 알고 있었는데, 노출 관점에서는 사본이 늘어나는 일이었다. 한 기능이 다른 관점에서는 반대로 작동할 수 있다는 걸 실제 산출물에서 본 셈이다.

그리고 프론트엔드에서 키를 지킬 방법이 없다는 게 확인되고 나니, 백엔드가 왜 필요한지가 처음으로 성능이나 규모가 아닌 이유로 설명됐다. **비밀을 둘 곳이 필요해서** 서버가 필요하다.
